## 二、Bug 清单（按严重度）

### P0 · 生产上正在崩（有运行日志为证）

**G1 溢出型州必崩（代码级）**
`scripts/gold_scope.py:276` 打印行：`NAD={c['nad_rows']:>7}`。
而 overflow 分支（第 158 行附近）把 `nad_rows` 设成 `None` → `TypeError: unsupported format string passed to NoneType.__format__`。
证据：run `39458896954` 的 `gold (NH)` job traceback 正指这一行。
后果：**所有“数据全在溢出包”的州（NH、NV…）永远跑不成**，而这个分支本来就是为它们写的。

**G2 只信账本、不信实物（与 preflight 自相矛盾）**
`gold_preflight.py` 明确写了“以 Release 实物为准，账本缺失降为 warning”，并会从实物重建 shards；
但 `gold_scope.py` 只读 `MANIFEST.shards`，账本缺 → 直接 `raise KeyError("MANIFEST 里没有任何 NAD 分片…")`。
证据：run `39458896954` 的 `gold (AK)`：实物有 23 个县片，scope 仍判“county 与 overflow 都空”。
后果：好数据被挡在门外，且报的是“红”，看不出是账本问题。

**G3 addrfeat 漏记即整州拒跑**
`gold_scope.py` 用账本 `assets` 判 addrfeat 是否存在；一仓断点续传会漏记（preflight 注释里已写明 ID 漏 43 个、实物在）。
缺 addrfeat 的县被整体剔除 → `raise KeyError("没有任何可加工的完整县")`。
证据：run `39458896954` 的 `gold (ID)`。

**G4 州级三数误判（口径冲突）**
`gold_preflight.py` 的 C4：`three_number_check.matches is False` → 直接判 error 拒跑。
但一仓县级口径下 matches 常态为 False（州级只做参考，见一仓离线用例 S12）。
后果：**合法封印的州被判 partial**，尤其大州（州级 BBox 必含邻州边角）。

### P1 · 与一仓新契约冲突（尚未爆发，铺州后必踩）

**G5 Overture 只认一个文件**
`index_assets()` 里 `a["overture"] = name` 是覆盖式赋值。
一仓县片模式按县出 `OVERTURE-US-<ST>-<fips>-<key>.parquet` → 结果只剩最后一个县的 Overture 可用。

**G6 分卷标签不支持**
工作流输入固定 `raw-US-<ST>-v1`，没有 `-p1/-p2`。
德州两卷（每卷 ≤1000 资产）→ 二仓只会拉第一卷，当成全州。
另：matrix 工作流没有“只重跑失败州”的入口，只能整批重来。

**G7 不认 `complete_partial`**
一仓新加：缺县强制放行时 `STATUS.phase=complete_partial`、`reference_check.failed_counties` 非空。
二仓 preflight 只把 failed 当 warning，没有“缺县就拒绝当完整”的判定；coalesce 也不读 phase。
后果：下游把缺县州当完整州加工。

**G8 退出码语义混淆**
`preflight/scope` 的 exit 2 表示“上游未就绪，等一仓收尾”。
但工作流一律当 failure 并上哨兵报警（AK/ID 那两条红就是“等上游”）。
应分流：未就绪 = 黄（跳过、不报警、不重试）；真崩 = 红。

### P2 · 质量与能力缺口

**G9 没有离线自测**
一仓有 17 个场景（含假 Release、假 HTTP），二仓零测试。本轮每条修复都必须配一个离线用例。

**G10 命名解析靠硬切**
`index_assets()` 用 `parts[3]`、`parts[-1]` 硬切文件名认县。
一仓现已保证 `shards[]` 带 `county_fips/county_key/county_name` → 应优先读字段，文件名只兜底。

**G11 `zero_nad_counties[].oa_rows` 恒为 None**
字段有、值没有来源，下游若按它算覆盖率会得 None。

**G12 无“失败州重跑”入口**
矩阵批量失败后只能整批重跑（会把已成功的州再跑一遍，白烧 runner 额度）。

## 四、与一仓的接口契约（硬约束，双方照此实现）

**标签**
- 单卷：`raw-US-<ST>-v1`
- 分卷：`raw-US-<ST>-v1-p<N>`（N 从 1 起，县按 fips 排序均分，各卷独立账本、独立封印）

**账本（MANIFEST.json）**
- `assets[]`：`{path, bytes, sha256, sha256_head}`；**不含** STATUS.json / MANIFEST.json / RELEASE_NOTES.md
- `shards[]`：`{kind: county|overflow, county_fips, county_key, county_name, file, rows, expected_rows, gz_bytes, sha256_gz, sha256_raw}`
- `reference_check`：`counties_ok / counties_empty / counties_failed / counties_total / failed_counties / county_union_ids / overflow_ids`
- `completeness`：四源各自“上游声明 vs 本地产出”
- `volume`：分卷时 `{index, total, state_total_counties, this_volume_counties, fips_range}`

**状态（STATUS.json）**
- `phase ∈ {collecting, complete, complete_partial}`
- `done`：完成的县 fips（可能含 `OUTOFSTATE` 历史值，按 5 位数字过滤才是县）
- `counties_done / counties_failed` 为真值

**命名**
- `NAD-US-<ST>-<fips>-<key>.ndjson.gz`
- `OVERTURE-US-<ST>-<fips>-<key>.parquet|geojson`
- `TIGER-US-<ST>-<fips>-addrfeat.zip`、`TIGER-US-<ST>-county-<fips>.geojson`
- `OA-US-<ST>-<源名>.zip`

**核验口径（一仓已固化，二仓必须照此判）**
- 县级是唯一硬门槛；州级三数咬合仅参考，**matches=False 不算失败**。
- 缺县：一仓默认阻断封印；显式放行时 phase=complete_partial，二仓必须读取并声明。
- 溢出型州（counties_empty=全部、数据全在 overflow）：合法，但产物必须声明“未做空间核验”。

## 五、验收标准

1. `SD / NH / NV / AK / ID` 五个州全链路（preflight → scope → coalesce → 发版）零人工干预通过。
2. 德州两卷合并后：县数 254、无重复县、Σ县片行数 == 县并集 + 溢出。
3. 任一州缺县/账本缺失/实物与账本不一致，都能在**日志里一句话说清**是哪种，而不是抛 traceback。
4. 离线自测全绿（≥6 场景），且新 bug 必须补一条用例才允许合入。
